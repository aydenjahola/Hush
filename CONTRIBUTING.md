# Contributing to Hush

Thanks for helping. Hush is small, so the rules are short. The full contributor docs are [on the website](https://aydenjahola.github.io/Hush/contributing/build-from-source/).

- **Build and unit tests.** You need Xcode 26 or later ([Build from source](https://aydenjahola.github.io/Hush/contributing/build-from-source/)). `make test` must pass.
- **Audio changes need the integration tests.** Any change to audio behaviour (engines, taps, aggregate devices, the process monitor, or how the mixer starts, swaps or stops engines) must pass `make integration-test` before it merges. The unit tests use fake engines, so they keep passing when real muting breaks. Setup (BlackHole 2ch and the Audio Recording permission) is in the [testing guide](https://aydenjahola.github.io/Hush/contributing/testing/#integration-tests). CI runs these tests only experimentally, so run them locally and mention it in your pull request.
- **Pull request titles.** Pull requests are squash-merged, and the squash commit uses the PR title as its message. release-please builds the version and changelog from those messages, so the **PR title** must be a [Conventional Commit](https://www.conventionalcommits.org/): `type(scope): summary`, where type is one of `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore` or `revert`, the scope is optional (any text without `)`), and `!` before the colon marks a breaking change. For example `fix(audio): keep the tap alive after sleep`. GitHub's default revert titles (`Revert "…"`) are accepted too. The **PR title** check fails otherwise; edit the title to fix it. The check skips pull requests opened by bots (Imgbot, Dependabot, …). Maintainers: give a bot PR a conventional title when squash-merging, for example `chore: optimize images`, or accept that it won't appear in the changelog.
- **Commits.** Commits inside your branch are squashed away, but Conventional Commit messages (`feat:`, `fix:`, `docs:`, `test:`, …) still help review. Keep pull requests small and focused.
- **Realtime code.** Nothing inside an IOProc may allocate, lock, log, call Objective-C or await.
